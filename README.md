Отправьте личному Telegram-боту ZIP-архив вашего Obsidian vault. Он создаст
темы по папкам, опубликует заметки и превратит `[[wikilinks]]` в переходы
между сообщениями. Следующая загрузка обновит изменённые заметки на месте.

Бот рассчитан на одного владельца или небольшой круг доверенных пользователей.
Доступ ограничивается числовыми Telegram ID.

```text
Obsidian vault                 Telegram-супергруппа с темами
├── Проекты/                   ├── 📁 Проекты
│   ├── Идея.md       →        │   ├── 📄 Идея
│   └── План.md                │   └── 📄 План
└── Дневник/                   ├── 📁 Дневник
    └── Сегодня.md             │   └── 📄 Сегодня
                               └── 🗂 Навигация: дерево и связи
```

## Возможности

- 📁 Создаёт **форум-темы** по папкам vault
- 📄 Публикует заметки как сообщения с полным Markdown-форматированием
- 🔗 Преобразует `[[wikilinks]]` в ссылки на Telegram-сообщения
- 🗂 Автоматически поддерживает тему «Навигация» с деревом папок и файлов
- 🕸 Строит кликабельную карту связей между заметками в формате `заметка → ссылки`
- 🔄 Повторная синхронизация обновляет только изменившиеся заметки
- ♻️ Повторно использует существующие темы и сообщения вместо создания дубликатов
- 📦 Принимает vault как ZIP-архив через Telegram
- 🔒 Принимает команды и архивы только от разрешённых Telegram ID

## Быстрый старт (локально)

Понадобятся Python 3.12 или новее, токен от [@BotFather](https://t.me/BotFather)
и супергруппа с включёнными темами. Добавьте бота в неё как администратора
с правом управления темами и отправки сообщений.

**Windows / PowerShell**

```powershell
git clone https://github.com/PraWek/ObsidianTelegramSync.git
cd ObsidianTelegramSync
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

<details>
<summary>Linux / macOS</summary>

```bash
git clone https://github.com/PraWek/ObsidianTelegramSync.git
cd ObsidianTelegramSync
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
```

После настройки `.env` запустите `.venv/bin/python main.py`.

</details>

Откройте `.env` и заполните `BOT_TOKEN` и `ALLOWED_USER_IDS`.
На Windows запустите:

```powershell
.\.venv\Scripts\python.exe main.py
```

В супергруппе отправьте `/setsupergroup` от своего аккаунта, затем загрузите
ZIP-архив боту в личные сообщения. Синхронизация начнётся автоматически.

Файл `.env` загружается при запуске. Переменные, уже заданные в окружении,
имеют приоритет над значениями из файла. `.env` исключён из Git.

## Доступ по Telegram ID

Укажите свой числовой Telegram ID в обязательной переменной `ALLOWED_USER_IDS`:

```dotenv
BOT_TOKEN=токен_вашего_бота
ALLOWED_USER_IDS=123456789
```

Используйте ID личного аккаунта, не `@username`, номер телефона или ID группы.
Для нескольких доверенных пользователей перечислите ID через запятую:

```dotenv
ALLOWED_USER_IDS=123456789,987654321
```

Проверка действует в личных сообщениях и группах до обработки любых команд,
ZIP-архивов и уведомлений о темах. Пользователи вне списка не могут менять
целевую супергруппу, запускать синхронизацию, загружать архивы или получать
сведения через `/status`, `/topics`, `/tree` и `/graph`.
Команды от имени группы или канала, включая анонимного администратора,
отклоняются: отправляйте их от своего личного аккаунта.
Для `/bindtopic` и `/bindnote` дополнительно нужны права администратора группы.

Если `ALLOWED_USER_IDS` отсутствует, пуст или содержит некорректные ID,
бот не запускается. После изменения списка перезапустите бота.

Все разрешённые пользователи управляют **одной общей супергруппой**.
Добавляйте только тех, кому доверяете доступ к синхронизации и смене группы:
список разрешённых ID не создаёт отдельных хранилищ для разных пользователей.
Опубликованные в группе заметки доступны её участникам независимо от этого списка.

## Деплой на Render

### Шаг 1 — Создать бота

1. Напишите [@BotFather](https://t.me/BotFather) → `/newbot`
2. Скопируйте токен

### Шаг 2 — Подготовить супергруппу

1. Создайте супергруппу в Telegram
2. Включите **Темы** (Settings → Topics → Enable)
3. Добавьте бота как администратора с правами:
   - ✅ Управление темами
   - ✅ Отправка сообщений

### Шаг 3 — Деплой

1. Создайте новый **Web Service** на [render.com](https://render.com)
2. Подключите этот репозиторий
3. Для Blueprint-деплоя выберите `render.yaml` в корне репозитория; для обычного Web Service используйте Dockerfile из корня.
4. В **Environment** укажите:
   - `BOT_TOKEN` — токен от BotFather
   - `ALLOWED_USER_IDS` — ваш числовой Telegram ID; несколько ID через запятую
   - `WEBHOOK_URL` — URL вашего сервиса на Render (после первого деплоя)
5. Задеплойте

### Шаг 4 — Зарегистрировать супергруппу

1. В вашей супергруппе напишите `/setsupergroup`
2. Боту в личку отправьте ZIP-архив vault

### Шаг 5 — Загрузить vault

1. Сожмите папку vault в ZIP
2. Отправьте ZIP-файл боту в личку (как документ, не фото)
3. Синхронизация запустится автоматически

## Переменные окружения

| Переменная | Описание | Обязательна |
|---|---|---|
| `BOT_TOKEN` | Токен от BotFather | ✅ |
| `ALLOWED_USER_IDS` | Разрешённые Telegram ID пользователей через запятую | ✅ |
| `WEBHOOK_URL` | URL Render-сервиса | Для деплоя |
| `SUPERGROUP_ID` | ID супергруппы | Нет (через /setsupergroup) |
| `PORT` | Порт (Render задаёт сам) | Нет |
| `WEBHOOK_SECRET` | Секрет для вебхука | Нет |
| `DB_PATH` | Путь к SQLite | Нет (по умолч. `data/sync.db`) |
| `MAX_MESSAGE_LENGTH` | Макс. длина сообщения | Нет (по умолч. 4000) |

### Двухпроходная синхронизация

Бот синхронизирует заметки в **два прохода**:

1. **Проход 1** — отправляет все заметки, получает ID сообщений
2. **Проход 2** — обновляет заметки с `[[wikilinks]]`, подставляя реальные ссылки

Это позволяет корректно разрешать взаимные ссылки между заметками.

## Повторная синхронизация

```
/sync
```

После каждой загрузки ZIP (и после `/sync`) бот:

1. Проверяет сохранённые соответствия **папка → тема Telegram** и **путь заметки → сообщение Telegram**.
2. Для новой папки ищет среди известных боту тем тему с таким же названием и использует её, если совпадение однозначное. Создаёт новую тему только если не нашёл подходящей.
3. Новые заметки отправляет в привязанную тему.
4. Изменённые заметки **редактирует на месте** (старое сообщение сохраняет ID).
5. Неизменённые заметки пропускает (сравнение по SHA-256 хешу Telegram-контента).

### Ранее созданные вручную темы и заметки

Telegram Bot API **не позволяет получить полный список старых тем и прочитать всю историю супергруппы**. Поэтому бот автоматически узнаёт названия тем, созданных/переименованных, пока он работает и получает уведомления Telegram, а также помнит темы, созданные им самим. Если тема существовала до добавления бота или база данных была потеряна, привяжите её вручную **один раз**:

- Откройте нужную существующую тему супергруппы и отправьте `/bindtopic Проекты/Идеи`. Путь должен **точно совпадать** с папкой в ZIP (для корневых заметок — `/bindtopic .`).
- Если старое сообщение заметки уже опубликовано **этим же ботом**, ответьте на то сообщение командой `/bindnote Проекты/Идеи/План.md`. При следующем ZIP бот отредактирует исходное сообщение вместо дублирования. Привязать чужое сообщение для редактирования нельзя.

Команды привязки доступны администраторам зарегистрированной супергруппы, чей Telegram ID включён в `ALLOWED_USER_IDS`. При неоднозначном совпадении имён тем синхронизация не создаёт дубликат вслепую: требуется явная `/bindtopic`.

**Важно:** не теряйте постоянное хранилище SQLite (`DB_PATH`), иначе сведения о заметках и темах, не восстановимые через Bot API, будут утрачены. В `render.yaml` уже предусмотрен диск `/data` и `DB_PATH=/data/sync.db`.

Сохранённые ZIP и файл выбранной группы пока записываются в `data/`
относительно рабочего каталога (`/app/data` в Docker). Render-диск `/data`
их не покрывает: после пересоздания контейнера может потребоваться повторная
загрузка ZIP и регистрация группы. Чтобы сохранить настройку группы отдельно
от этого файла, задайте `SUPERGROUP_ID` в окружении.

## Команды бота

| Команда | Описание |
|---|---|
| `/start` или `/help` | Инструкция |
| `/setsupergroup` | Зарегистрировать текущую группу |
| `/sync` | Повторная синхронизация |
| `/status` | Статус последней синхронизации |
| `/topics` | Список созданных тем |
| `/bindtopic Путь/Папки` | Связать текущую существующую тему с папкой Obsidian |
| `/bindnote Путь/Заметка.md` | Ответом на сообщение бота связать его с заметкой |

| `/graph` | Открыть карту связей заметок |
| `/upload` | Как загрузить vault |

## Навигация и граф связей

После каждой синхронизации бот создаёт (или обновляет) отдельную тему
**«🗂 Навигация»**. В ней находятся два сообщения:

- **Дерево vault** — папки и файлы с переходами к соответствующим сообщениям;
- **Карта связей** — компактный аналог графа Obsidian: каждая строка показывает
  заметку и все заметки, на которые она ссылается. Все узлы в строках кликабельны.

Telegram не поддерживает интерактивный граф с перетаскиваемыми узлами внутри
чата, поэтому карта представлена как обновляемый список связей. Это сохраняет
главное свойство графа — быстрый переход по отношениям заметок — прямо в группе.

## Разработка и тесты

Тесты работают без Telegram-токена и без обращения к Telegram API.
После установки зависимостей запустите:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

На Linux / macOS используйте `.venv/bin/python` вместо Windows-пути.
GitHub Actions запускает этот набор на Windows и Linux с Python 3.12 и 3.14
при отправке коммитов и открытии pull request.

Об ошибках можно сообщить через [Issues](https://github.com/PraWek/ObsidianTelegramSync/issues/new/choose).
Приложите шаги воспроизведения и небольшой пример заметки без личных данных.
